1. INTRODUCTION
--------------------------------------------------------------------------------
  1.1  Background and Motivation
       - The electoral roll as the foundation of democratic participation
       - Special Intensive Revision (SIR) 2025-26 and public debate on
         deletions
  1.2  Problem Statement
       - ECI publishes rolls as flattened raster PDFs
       - No machine-readable access means no independent audit
       - Hindi script, poor scans, bilingual layout, scale (lakhs of pages)
  1.3  Research Questions
       - RQ1: Can a low-cost, CPU-only pipeline recover roll data accurately
              enough for auditing?
       - RQ2: How do consensus, voting and cross-document memory improve
              accuracy over single-pass OCR?
       - RQ3: What patterns of addition, deletion and modification appear
              across booths, age groups and gender during SIR?
  1.4  Contributions
       - C1: Open, reproducible OCR + transliteration pipeline
       - C2: Hand-labelled benchmark of electoral roll cards
       - C3: Empirical audit of roll changes in N constituencies
       - C4: Ethical framework for research on voter-roll data
  1.5  Paper Organisation

5. METHODOLOGY I - THE OCR PIPELINE
--------------------------------------------------------------------------------
  5.1  System Overview (architecture diagram)
  5.2  Pre-processing
       5.2.1  PDF rasterisation (300 dpi)
       5.2.2  Page classification: cover / main roll / additions /
              deletions / modifications / summary
  5.3  Cover Page Parsing
       5.3.1  Regex extraction of identifiers and elector counts
       5.3.2  Cross-checking against file names
  5.4  Layout Analysis
       5.4.1  Card grid detection from printed borders
       5.4.2  Serial and section box detection
       5.4.3  Filtering non-voter cells
  5.5  Field Recognition
       5.5.1  EPIC: multi-scale, whitelist passes + majority vote
       5.5.2  Name and relation name: bilingual + Hindi-only passes
       5.5.3  Age, gender, relation type: digit whitelist, fuzzy matching
       5.5.4  Serial numbers and action markers (shifted / modified)
  5.6  Consensus and Error Repair
       5.6.1  Per-field voting
       5.6.2  Page- and PDF-level name consensus
       5.6.3  Cross-document Hindi name memory (2-PDF confirmation rule)
  5.7  Transliteration (Hindi -> English)
       5.7.1  Rule-based syllabification and schwa deletion
       5.7.2  Learned context re-ranker
       5.7.3  Lexicon and override layer
  5.8  Uncertainty Flagging ("flag, don't guess")
       5.8.1  Flag taxonomy (epic_low_conf, name_garbled, ...)
       5.8.2  Hybrid mode: routing flagged cards to a vision model
  5.9  Merge, Deduplication and Validation
  5.10 Implementation and Resource Footprint
       - Hardware (2 vCPU / 4 GB), throughput, cost per page
